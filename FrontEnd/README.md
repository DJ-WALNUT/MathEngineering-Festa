# 수리공학 페스타 프론트엔드

React + Vite + TypeScript + Tailwind CSS v4. Cloudflare Pages 배포용.

## 실행

```bash
cd FrontEnd
npm install
npm run dev      # http://localhost:5173
```

개발 중에는 `/api` 요청이 vite 프록시를 통해 `http://127.0.0.1:8000` 으로 넘어가므로
CORS 설정 없이도 백엔드와 붙는다.

```bash
npm run build      # 타입 체크 + 프로덕션 빌드
npm run typecheck  # 타입만 확인
```

## 디자인

'이공공이 2002' 포스터의 Y2K 레트로를 그대로 옮겼다 — 붉은 망점 배경, 노란 '2002',
크림 종이, 검은 픽셀 테두리, 피처폰 문자창의 파랑, 픽셀 하트. 팔레트는
`src/index.css` 의 `@theme` 한 블록이고, 이것만 갈아끼우면 전 페이지가 따라온다.

| 토큰 | 쓰임 |
|---|---|
| `sand-*` | 크림 종이 — 바탕 · 카드 안쪽 · 흐린 테두리 |
| `cobalt-*` | 문자창 · 브라우저 창 제목줄의 파랑 — 주 버튼 · 링크 · 강조 · **1부 교류전** |
| `flame-*` | 포스터의 주황 — 주의 상태 · 보조 버튼([답장]) |
| `brick-*` | 망점 배경의 짙은 빨강 — 오류 · 헤더 로고 · 푸터 바탕 |
| `heart-*` | 픽셀 하트 — **2부 솔로파티** 전용. 1부(파랑)와 한눈에 갈려야 한다 |
| `gold-*` | '2002' 의 노랑 — 형광펜(`.mark`) · 신청 칸 · 카카오 |
| `ink-*` | 픽셀 테두리와 같은 잉크 검정 — 본문 글자 |

공통 클래스는 `@layer components` 에 있다.

- `.card` — 검은 2px 테두리에 오른쪽 아래로 딱 떨어지는 그림자. 포스터의 브라우저 창
- `.window-bar` `.window-dots` — 창 제목줄(파랑)과 왼쪽 동그라미 셋
- `.btn-primary` `.btn-secondary` `.btn-ghost` — 피처폰 문자창의 [메뉴](파랑) · [답장](주황) · 납작한 것
- `.halftone` `.halftone-light` — 망점. 푸터는 짙게, 바탕은 옅게
- `.bunting` — 포스터 위쪽의 만국기 (맨 위 띠)
- `.speech-bubble` — 문자 말풍선 · `.mark` — 노란 형광펜
- `.font-pixel` `.font-pixel-small` — 픽셀 글꼴(Galmuri 14 / 11). 안티앨리어싱을 꺼서 또렷하게 선다

**글꼴** — 픽셀 글꼴 [Galmuri](https://github.com/quiple/galmuri)(SIL OFL)를 `public/fonts/` 에
자체 호스팅한다. 제목 · 이름표 · 숫자에만 쓰고 본문은 Pretendard(jsDelivr) 그대로다.
비트맵 글꼴을 본문에 쓰면 긴 안내문이 읽기 힘들다.

**행사 이름은 그림이 아니라 글자다.** 지난 행사는 포스터의 글자를 PNG 로 잘라 썼지만,
이번 포스터의 제목은 픽셀 글꼴이라 웹폰트로 그대로 다시 세울 수 있다.
`Decorations.tsx` 의 `<Wordmark />` 가 흰 '이공공이' + 노란 '2002' 에 검은 픽셀
테두리(`.wordmark-outline`, 여덟 방향 text-shadow)를 두른다. 글자를 바꾸려면
`event.ts` 의 `name` · `edition` 만 고치면 된다.

**포스터 그림** — `public/poster/` 에 배너(히어로)와 카드 뉴스 여섯 장이 있다. 원본
PNG(3240px)를 webp 1200~2000px 로 줄인 것이라 한 장에 50~170KB 다. 홈의
`POSTER_CARDS`(`data/event.ts`)가 목록이고, 새 카드는 파일을 넣고 한 줄 더하면 된다.

장식 그래픽(픽셀 하트 · 별 · 게임패드 · 봉투 · 반짝임)은 `Decorations.tsx` 의
`PixelArt` 가 **문자열 격자를 SVG 네모로 편** 것이다. 글자 하나가 픽셀 하나이고
`shape-rendering: crispEdges` 라 어느 크기로 키워도 흐려지지 않는다.

> Tailwind v4 는 `@apply` 로 다른 컴포넌트 클래스를 참조할 수 없다.
> (`.btn-primary { @apply btn ... }` 는 빌드 에러) 공통 속성은 선택자를 나열해 공유한다.

## 내용을 고치는 곳

행사 정보는 전부 `src/data/` 에 하드코딩되어 있다. 이 파일들만 고치면 사이트 전체에 반영된다.

| 파일 | 내용 |
|---|---|
| `src/data/event.ts` | 일시 · 장소 · 참가비 · 계좌 · 연락처 · 공지 · 준비물 · 신청 차수 · 상단 메뉴 |
| `src/data/timetable.ts` | 타임테이블 · 분류 배지 색 — **지금은 비어 있다** |
| `src/data/badge.ts` | 명찰 서식 · `BADGE_READY` 스위치 — **지금은 꺼져 있다** |

`// TODO:` 로 표시된 값은 아직 확정되지 않은 자리표시자다.

신청 차수(`EVENT.applyPhases`)는 `startsAt ~ endsAt` 사이에 든 차수만 자동으로 열린다.
날짜만 적어 두면 배포 없이 차수가 넘어가고, `formUrl` 을 비워 두면 버튼이 '준비 중' 으로 잠긴다.

### 참가비는 두 겹이다

본 행사비(총학생회비 납부자 / 미납부자)가 아래에 깔리고, **뒤풀이에 가는 사람만**
그 위에 뒤풀이비가 얹힌다. 화면에 적는 숫자는 `EVENT.fees` 에 있지만 **실제 청구액은
백엔드가 정하므로**(`BackEnd/.env` 의 `FEE_*`) 두 곳을 같은 값으로 맞춰야 한다.

뒤풀이비는 별도 안내로 나중에 걷는다. 그래서 아직 안 낸 것이 본 행사의 '미납'이 되지
않고, 납입 확인 화면(`/payment`)에서도 두 줄로 갈라 보여 준다 — 한 줄로 합치면
"본 행사비는 다 냈는데 왜 남은 금액이 뜨냐"는 문의가 그대로 들어온다.

### 아직 비어 있는 것

| 무엇 | 지금 상태 | 채우는 법 |
|---|---|---|
| 타임테이블 | `/schedule` 이 '준비 중'을 띄우고 메뉴에서도 빠져 있다 | `timetable.ts` 의 `sessions` 를 채우고 `event.ts` 의 `NAV_LINKS` 에서 그 줄의 주석을 푼다 |
| 명찰 | 관리자 > 명찰이 '준비 중'을 띄우고 인쇄를 막는다 | `badge.ts` 의 좌표·글꼴·배경을 새 시안으로 바꾸고 `BADGE_READY = true` |
| 내 업무 | 관리자 > 내 업무가 '준비 중'을 띄운다 | 새 양식을 받아 `data/staffDuties.ts` 를 만들고 `DutyPanel.tsx` 를 다시 쓴다 |

## 명찰

> ⚠️ **지금은 잠겨 있다.** `src/data/badge.ts` 의 `BADGE_READY` 가 `false` 라서
> 관리자 > 명찰 탭은 '준비 중'을 띄우고 인쇄 버튼을 내준다. 이번 행사는 디자인과
> 글꼴이 통째로 바뀌는데, **그리는 코드는 멀쩡해서 누르면 지난 행사의 서식이
> 그대로 150장 나오기 때문이다.** 인쇄소로 넘어가면 되돌릴 수 없다.
>
> 새 시안을 받으면 배경 PNG 세 장 · 글꼴 · 좌표를 아래 설명대로 갈아끼운 뒤
> `BADGE_READY = true` 로 바꾼다. 아래 내용은 그때 그대로 쓸 수 있다.

디자인 원본은 포토샵 파일(`명찰 최종본.psd`)이고, 아트보드 네 장(스태프 앞뒤 ·
참가자 앞뒤)이 각각 `1240 × 1754px @300dpi` — 실물로는 **A6(105 × 148.5mm)** 다.

**배경은 그리지 않고 굽는다.** 로고 · STAFF/GUEST 띠 · 일정표에는 그레이디언트와
엠보싱과 그림자가 겹겹이 걸려 있어, 브라우저로 흉내 내면 반드시 시안과 달라진다.
그래서 포토샵이 만든 병합본에서 **사람마다 달라지는 것만 지워** PNG 로 구워 두고,
그 위에 글자와 QR 만 얹는다.

```
public/badge/front-staff.png   앞면 — STAFF 띠, 개인 QR 없음
public/badge/front-guest.png   앞면 — GUEST 띠, 오른쪽 아래에 개인 QR 자리
public/badge/back.png          뒷면 — 일정표. 스태프 · 참가자가 같다
```

배경을 다시 구우려면 (시안이 바뀌었을 때):

```bash
pip install psd-tools pillow
python scripts/build-badge-background.py ~/Downloads/'명찰 최종본.psd'
```

얹는 것은 `src/data/badge.ts` 가 정한다. 좌표는 전부 **원본 픽셀 그대로**이고,
명찰 한 장은 그 좌표계를 그대로 쓰는 SVG 라서 어떤 크기로 뽑아도 시안에서 밀리지
않는다. 사람마다 달라지는 것은 앞면 셋뿐이다.

| | 내용 | 글꼴 |
|---|---|---|
| 학과 | `department` | GmarketSans Medium 50px |
| 이름 | `name` | GmarketSans Bold 250px |
| 조 | `groupValue` | GmarketSans Medium 50px |

시안은 세 글자 이름에 맞춰 잡혀 있다. 네 글자 이상이면 이름칸을 넘으므로 **넘칠
때만** 그 폭에 눌러 그린다(`maxWidth`).

학과명은 수집 경로에서 폼 안내 문구를 떼어 낸다 — `자연공학계열 (26년도 기준, 1학년만
선택 가능)` 은 학과 이름이 아니라 폼을 채우는 사람에게 하는 말이라, 그대로 두면 명찰에
그 문장이 인쇄되고 같은 학과가 둘로 갈린다. 이미 들어와 있는 것은
`python scripts/clean_departments.py --apply` 로 한 번 정리한다.

앞면이 STAFF 로 나갈지 GUEST 로 나갈지는 명단의 `isStaff` 하나가 정한다 —
관리자 &gt; 참가자에서 요금 구분을 '스태프'로 둔 사람이다.

### QR

뒷면 세 개(지도 · 마이페이지 · 인스타)는 모두에게 같아 한 번만 만든다. 앞면 하나는
사람마다 다른 개인 카드(`/p/<token>`)이고, 이것이 외출 태그의 열쇠다. **스태프
앞면에는 개인 QR 이 없다**(시안대로. 넣으려면 `front.qrOnStaff` 를 켠다).

QR 에 담기는 주소는 `siteOrigin` 이 정한다. **인쇄한 브라우저의 주소를 쓰지
않는다** — 미리보기 도메인에서 뽑으면 150장에 그 주소가 박히기 때문이다.

뒷면 QR 은 작다. 흰 칸이 84px 뿐이라, 사방에 4모듈치 밝은 여백(조용한 구역)을
남기면서 키울 수 있는 최대가 64px(5.4mm)이고 모듈 하나가 0.22mm 다. 더 키우면
모듈은 커지지만 여백이 깎여 오히려 안 읽힌다 — 칸 밖은 어두운 들판 그림이다.
정말 더 키우려면 주소를 17자 이내로 줄여 25모듈을 21모듈로 떨어뜨려야 한다.

### 인쇄

관리자 &gt; 명찰에서 **앞면 N장 인쇄**를 누른다. **한 페이지에 한 장씩** 여백 없이
나온다 — 용지가 곧 명찰 크기라 재단선을 맞춰 자를 일이 없다.

**뒷면은 사람 수만큼 찍지 않는다.** 모두에게 똑같아서 150번 반복될 뿐이다. 옆의
**뒷면 1장** 버튼으로 한 장만 뽑아 인쇄소에 맡긴다.

**용지 A6(105 × 148.5mm) · 배율 100%(실제 크기) · 여백 없음.** '페이지에 맞춤' 으로
두면 A6 가 아닌 크기로 나와 케이스에 들어가지 않는다. 가장자리를 못 찍는 프린터라면
`sheet.safeMarginMm` 을 5 정도로 주고 뽑은 뒤 재단한다.

## 페이지

| 경로 | 내용 |
|---|---|
| `/` | 개요 · D-day · 참가비 · 계좌 · 준비물 · 문의 |
| `/schedule` | 타임테이블 (요강 확정 전까지 '준비 중') |
| `/payment` | **본인 납입 확인 + 참가 확정 상태** (이름 + 전화번호) · 뒤풀이비 별도 표시 |
| `/checkin` | **셀프 체크인** (이름 + 학번 + 전화 뒤 4자리) · 럭키드로우 번호 |
| `/p/:token` | 개인 카드 — 명찰 QR 이 가리키는 화면 |
| `/admin` | 관리자 (대시보드 · 입금 · 참가자 · 배정 · 명찰 · 출석 · 작업 기록) |
| `/admin/draw` | **럭키드로우 추첨** — 프로젝터용 전체 화면 연출 (관리자 인증 공유) |

`/checkin` 은 입구 QR 로만 들어오는 화면이라 **네비게이션에 넣지 않는다.** QR 이미지는
관리자 페이지 → 출석 → 체크인 QR 에서 만들고 인쇄한다(`qrcode` 패키지, 외부 요청 없음).

**QR 은 하나이고 자리는 여럿이다.** 낮의 본 행사와 저녁의 뒤풀이가 같은 QR 을 쓰고,
찍은 사람은 그때 **열려 있는 회차**에 들어간다(관리자 > 출석에서 연다). 그래서 성공
화면 맨 위에 회차 이름을 띄운다 — 말해 주지 않으면 참가자는 자기가 어디에 찍힌 것인지
알 수 없다.

체크인에 성공하면 이름과 조를 크게 띄운다. 그 화면을 스태프에게 보여 주고 명찰과 간식을
받는 흐름이라, 이름을 마스킹하지 않는다 — 이름 · 학번 · 전화 뒷자리 세 가지를 모두 맞춘
뒤이므로 본인으로 본다.

성공 화면은 **`localStorage` 에 남아 새로고침해도 그대로 열린다.** 모바일 크롬은 탭을 오래
놔두면 돌아왔을 때 알아서 새로고침해 버리는데, 그때마다 학번과 전화번호를 다시 물으면
조를 확인하려는 사람이 입력을 반복하게 된다. `sessionStorage` 는 탭이 정리되면 함께
사라져 이 용도로 쓸 수 없다.

- 24시간이 지나면 알아서 비워진다 (당일 일정을 넉넉히 덮는 값). 판정은 화면을
  여는 순간에만 하고, 그때마다 시각이 갱신되므로 행사 중에 몇 번 열어보면
  사실상 만료되지 않는다.
- 화면을 다시 볼 때(첫 진입 · 탭 복귀 · 홈에서 돌아옴) 마지막으로 받은 지 1분이
  지났으면 **조용히 최신 배정을 받아온다.** 조나 표시 항목이 현장에서 바뀌면
  캐시된 옛 정보를 스태프에게 보여주게 되기 때문이다. 실패하면(창구가 닫혔거나
  통신이 끊겼거나) 보관된 화면을 그대로 둔다.
- 1분을 두는 이유는 행사장에서 수백 명이 같은 IP 를 타기 때문이다.
  열 때마다 부르면 rate limit 을 헛되이 먹는다.
- 기기를 빌려주거나 다른 사람이 체크인해야 하면 상단 **다시 입력하기** 로 비운다.

체크인 화면에는 조 아래에 **럭키드로우 번호**가 금색 띠로 함께 뜬다. 조는 접수처에서
스태프가 보는 값이고 번호는 몇 시간 뒤 본인이 찾는 값이라 쓰임이 갈리므로, 색을 아예
달리해 한 화면에서 헷갈리지 않게 했다 (추첨 화면도 같은 금색이다).

## 럭키드로우 추첨 화면 (`/admin/draw`)

프로젝터에 띄우는 전체 화면이다. **관리자 하위 경로**이고 인증도 관리자와 같은 것을
쓴다(`pages/admin/AdminSession.tsx`) — 주소를 알아냈다고 열리지 않는다. 관리자 헤더와
탭을 쓰지 않는 이유는 네비게이션과 표가 함께 보이면 연출이 죽기 때문이고, 별도
화면인 이유는 추첨을 흔히 **강당의 다른 기기**에서 띄우기 때문이다.

인증을 `AdminSession.tsx` 한 곳에 모은 이유는 화면마다 따로 두면 한쪽만 느슨해지기
때문이다. 실제로 이 화면은 처음에 '토큰이 있는가'만 보고 통과시켜, 만료된 토큰으로도
화면이 열린 뒤 API 호출에서야 튕겼다. 지금은 관리자 화면과 똑같이 **서버에 세션을
확인한 뒤** 들어간다.

### 진행자가 멈춘다

릴은 시작하면 **계속 돈다.** 진행자가 신호를 줘야 선다. 타이머로 알아서 멈추면
"지금이다" 하는 순간을 진행자가 잡을 수 없다.

| 키 | 하는 일 |
|---|---|
| `Enter` `Space` `→` `PageDown` | **한 번이면 왼쪽부터 차례로** (2.6초 간격) |
| `A` `S` `D` | 백 / 십 / 일의 자리만 바로 |

기본을 '한 번에 끝까지'로 둔 이유는 진행자가 대개 마이크를 들고 있기 때문이다.
자리마다 키를 찾아 누르게 하면 정작 관객을 못 본다. 자리를 끊어 보고 싶을 때만
`A`/`S`/`D` 로 끼어들면 되고, 그때 예약되어 있던 신호는 이미 선 자리라 그냥 흘러간다.
차례로 멈추는 중에 `Enter` 를 연타해도 리듬이 빨라지지 않는다.

키는 `event.code` 로 읽으므로 **한/영 상태와 무관하다.** 무대에서 한글 자판인 채로
`A` 를 눌러 'ㅁ' 이 들어오는 상황이 실제로 생긴다. 터치 화면이나 키를 못 쓰는
상황을 위해 같은 동작의 버튼도 슬롯 아래에 함께 둔다. 조작판에서 **키 없이 자동으로
멈춤**을 켜면 시작과 동시에 알아서 선다 (무인 시연용).

### 연출 — 자릿수를 하나씩 잠그며 후보를 좁힌다

```
247명  →  1__ 100명  →  13_ 10명  →  137 1명
```

릴이 멈출 때마다 **화면 아래 번호판에서 탈락한 번호가 실제로 꺼진다.** 자기 번호를
벽에서 찾아 둔 사람은 백의 자리가 잠기는 순간 자기가 살았는지 죽었는지 바로 안다.
숫자가 그냥 돌다 멈추는 것보다 이쪽이 훨씬 시끄럽다 — 탈락이 한꺼번에 일어나므로
탄식도 한꺼번에 나온다.

**결과가 정해진 자리에서는 뜸을 들이지 않는다.** 80명이 체크인했다면 번호는 001~080
이고 백의 자리는 어차피 0 이다. 후보 전원이 같은 숫자를 쓰는 자리는 처음부터 확정으로
띄우고(`0 ? ?`), 실제로 갈리는 자리에만 시간을 쓴다.

- **번호판이 꺼지는 건 릴이 실제로 선 순간이다.** 키를 누른 순간 꺼지면 아직 돌고
  있는 숫자를 화면이 먼저 알아버린 꼴이 된다. 그래서 감속이 끝나는 시점에 맞춘다.
- 릴의 움직임은 React 가 아니라 `Reel` 이 DOM 을 직접 몬다. 돌 때는 CSS keyframe 으로
  등속 회전하고, 멈추라는 신호가 오면 **그 순간의 `transform` 을 읽어** 거기서부터
  목표 숫자까지 감속 transition 을 이어 붙인다. keyframe 을 그냥 걷어내면 위치가
  0 으로 튀어 릴이 순간이동한 것처럼 보인다.
- 소리는 파일 없이 `AudioContext` 오실레이터로 만든다(정지 틱 · 당첨 아르페지오).
  첫 소리가 버튼 클릭 뒤에 나므로 자동재생 정책에도 걸리지 않는다. 끌 수 있다.
- 꽃가루도 라이브러리 없이 CSS 애니메이션이다. **외부 요청이 하나도 없다.**

### 조작판은 무대를 밀어내지 않는다

진행자용 조작판(상품 등록 · 추첨 조건 · 당첨 이력)은 **왼쪽에 겹쳐 뜨는 서랍**이다.
위에서 밀고 들어오는 방식이면 여닫을 때마다 슬롯이 아래로 내려갔다 올라와 연출이
흔들린다. 지금은 조작판을 여닫아도 무대가 한 픽셀도 움직이지 않는다.

시연으로 몇 번 돌려 보고 나면 조작판의 당첨 이력에서 **전체 삭제**로 흔적을 지운다.
상품 수량과 후보가 처음 상태로 돌아가고 체크인 번호는 그대로 유지된다. 되돌릴 수
없지만 지운 사실은 관리자 &gt; 작업 기록에 남는다.

**이번 회차에 걸 상품은 슬롯 바로 아래에서 고른다.** 조작판을 열지 않고도
'고르고 → 돌린다'가 한 동선에서 끝나야 하기 때문이다. 상품 자체는 행사 전에
조작판에서 한꺼번에 등록해 두고(남은 수량은 알아서 센다), 당일에는 고르기만 한다.
당첨 카드에는 상품과 사람(번호 · 이름 · 학과 · 조)이 함께 뜬다 — 시상은 둘이
짝지어야 성립한다.

### 결과는 연출로 정하지 않는다

번호는 서버가 뽑는 순간 고르고 그 자리에서 DB 에 박는다. 이 화면이 하는 일은 이미
정해진 번호를 자릿수별로 드러내는 것뿐이다. 무작위로 릴을 돌려 나온 값을 결과로
삼으면 250명이 체크인한 자리에서 287번이 나온다.

번호판 타일에는 **번호만 있고 이름이 없다.** 스크린에 띄우는 화면이라 이름을 함께
받으면 명단이 그대로 공개되는 셈이 된다.

관리자 세션 토큰은 `sessionStorage` 에 담고 `Authorization: Bearer` 로 보낸다.
쿠키를 쓰지 않으므로 프론트와 백엔드 도메인이 달라도 SameSite 문제가 생기지 않는다.

## 숫자로 조절하는 것들

느낌을 다듬는 값은 전부 **파일 맨 위의 이름 붙은 상수**로 빼 두었다. 코드를 읽지 않고
숫자만 바꿔도 되고, 이름으로 검색하면 바로 찾을 수 있다. 아래 표의 값은 현재 설정이다.

### 추첨 연출 — `src/pages/DrawPage.tsx`

무대에서 체감이 가장 크게 갈리는 값들이다. 시연해 보고 맞춘다.

| 이름 | 지금 | 뜻 |
|---|---|---|
| `DECEL_MS` | `1600` | 멈춤 신호를 받고 실제로 서기까지. 짧으면 힘없이 선다 |
| `STOP_GAP_MS` | `2600` | `Enter` 로 차례차례 세울 때 한 자리와 다음 자리 사이 |
| `REVEAL_DELAY_MS` | `700` | 마지막 자리가 선 뒤 당첨자를 띄우기까지의 뜸 |
| `AUTO_FIRST_MS` | `2600` | 자동 정지를 켰을 때 첫 자리가 서기까지 |
| `DECEL_LOOPS` | `2` | 설 때 몇 바퀴 더 돌고 설지 |
| `POSITION_KEYS` · `NEXT_KEYS` | `A S D` · `Enter` 등 | 정지 단축키. `event.code` 라 한/영 상태와 무관하다 |

릴이 도는 모습과 서는 '덜컥' 은 `index.css` 의 `@keyframes reel-roll` · `reel-clunk` 이고,
꽃가루는 `confetti-fall` 이다.

### 체크인 화면 — `src/pages/CheckInPage.tsx`

| 이름 | 지금 | 뜻 |
|---|---|---|
| `KEEP_MS` | `24시간` | 성공 화면을 기기에 얼마나 보관할지 (당일 일정을 넉넉히 덮는 값) |
| `REFRESH_AFTER_MS` | `1분` | 화면을 다시 열었을 때 조용히 최신 배정을 받아오는 최소 간격. **내리면 행사장에서 rate limit 을 먹는다** (수백 명이 같은 IP 를 탄다) |

관리자 출석판이 스스로 새로 고치는 간격은 `pages/admin/AttendancePanel.tsx` 의 `REFRESH_MS`(15초).

### 색과 모양 — `src/index.css`

맨 위 `@theme` 블록이 팔레트 전부다. 색값 하나를 바꾸면 그 색을 쓰는 모든 화면이 같이 바뀐다.
공통 모양(`.card` `.btn-primary` `.gingham` …)은 `@layer components` 에 모여 있다.

### 손대지 않는 것

| 대상 | 이유 |
|---|---|
| `AssignmentsPanel.tsx` 의 `PAGE_SIZE` | 목록 API 의 **서버 상한과 같은 값**이다. 올려도 더 받아오지 못한다 |
| `lib/api.ts` 의 `API_BASE` | 코드가 아니라 `VITE_API_BASE_URL` 환경 변수로 정한다 |

## Cloudflare Pages 배포

**설정 > 빌드**

| 항목 | 값 |
|---|---|
| 프레임워크 프리셋 | Vite |
| 빌드 명령 | `npm run build` |
| 빌드 출력 디렉터리 | `dist` |
| 루트 디렉터리 | `FrontEnd` |

**환경 변수** (Production / Preview 모두)

```
VITE_API_BASE_URL = https://api.도메인
```

`public/_redirects` 가 SPA 라우팅을 처리하므로 `/payment` 같은 주소로 직접 들어와도 동작한다.

배포 후 백엔드 `.env` 의 `CORS_ORIGINS` 에 Pages 도메인과 커스텀 도메인을 **모두** 넣어야 한다.
빠뜨리면 조회가 CORS 로 막힌다.

# 수리공학 페스타 특설 페이지

타임테이블 · **참가비 납입 실시간 확인** · 당일 운영

```
FrontEnd/   React + Vite + TypeScript + Tailwind v4   → Cloudflare Pages
BackEnd/    Flask + SQLite                             → 시놀로지 Container Manager
```

지난 행사(공과대학 총MT)의 코드를 그대로 이어받되, **하루짜리 행사**에 맞게 고쳤다.
숙소도 버스도 없으므로 장소 지도 · 방/버스 배정 · 외출 태그는 통째로 걷어냈고,
대신 **참가비가 두 겹**이고 **출석이 두 번** 일어나는 구조가 새로 들어왔다.

백엔드가 다루는 것은 여전히 **돈과 명단** 둘뿐이다.

```
납입 완료 ──▶ 참가 확정 ──▶ 조 배정 ──▶ 당일 체크인 ──▶ 럭키드로우
             (사람이 누름)   (확정자만)    (확정자만)      (체크인 순서가 번호)
```

앞 단계를 건너뛰면 뒷 단계가 열리지 않는다. 입금이 확인됐다고 자동으로 확정되지 않고,
확정되지 않은 사람에게는 조를 배정할 수도 체크인을 받을 수도 없다.

## 참가비는 두 겹이다

| | 총학생회비 납부자 | 미납부자 |
|---|---|---|
| **본 행사** | 5,000원 | 7,000원 |
| **뒤풀이** (참가자만) | +10,000원 | +10,000원 |

뒤풀이비는 납부 여부와 무관하게 같고, **별도 안내를 통해 나중에 걷는다.** 여기가 설계의
핵심이다 — 두 겹을 한 덩어리로 세면 뒤풀이 신청자 전원이 안내가 나가기도 전에 '미납'으로
물들어 본 행사 확정이 막힌다.

그래서 들어온 돈을 **본 행사비부터 채우고** 남는 것을 뒤풀이비로 넘긴다. 납입 상태도
둘로 갈라 센다 — 확정 · 배정 · 출석의 문을 여는 것은 본 행사비 쪽뿐이고, 뒤풀이비는
배지로만 드러난다.

**안내가 나가기 전에 이미 합쳐 보낸 사람이 있다.** 입금 1건이 총 청구액을 덮었으면
&lsquo;합산 납부&rsquo; 배지를 붙여 명단에서 갈라 보여 준다. 갈라 두지 않으면 그 사람에게
안내를 한 번 더 보내고, 받은 사람은 한 번 더 낸다.

## 출석은 두 번 일어난다

낮의 **본 행사**가 있고, 신청자 중 일부만 남는 **뒤풀이**가 저녁에 따로 있다.
두 자리는 인원도 여닫는 시각도 다르다.

회차를 코드에 두 개 박지 않고 **데이터로 둔다**(배정 항목과 같은 방식). 현장에서
&lsquo;2부도 따로 세자&rsquo;가 나와도 관리자 화면에서 회차를 하나 더 만들면 끝이고,
재배포가 필요하지 않다.

들어오는 길은 둘이다.

- **셀프** — 참가자가 입구 QR 을 찍고 이름 · 학번 · 전화 뒷자리를 넣는다.
  회차가 열려 있을 때만 받는다. 인원이 많은 본 행사에 쓴다.
- **수동** — 관리자가 명단에서 이름을 찾아 누른다. **창구가 닫혀 있어도 된다.**
  인원이 적고 자리가 어수선한 뒤풀이는 대개 이쪽만 쓴다.

QR 은 하나다. 참가자는 회차를 고르지 않고 **그때 열려 있는 자리**에 찍히므로, 체크인
성공 화면 맨 위에 회차 이름을 띄운다.

## 럭키드로우 — 번호는 하나, 후보는 자리마다

번호는 **본 행사 체크인 순서**로만 준다(`001`, `002`, …). 회차마다 새로 매기면 참가자가
번호를 두 개 외워야 한다.

뒤풀이에서 뽑을 때는 같은 번호를 쓰되 **후보를 그 자리에 남은 사람으로 좁힌다.** 낮에만
왔던 사람의 번호는 번호판에서 처음부터 꺼져 있어, 참가자는 자기가 후보인지 한눈에 안다.

추첨은 프로젝터용 전체 화면(`/admin/draw`, 관리자 인증 공유)에서 한다. 릴은 시작하면
계속 돌고 **진행자가 신호를 줘야 선다.**

```
247명  →  1__ 100명  →  13_ 10명  →  137 1명

Enter · Space  한 번이면 차례로        A / S / D  그 자리만 바로
```

**당첨 번호는 서버가 뽑는 순간 정해져 DB 에 박힌다.** 화면은 이미 정해진 번호를
자릿수별로 드러내는 연출일 뿐이다. 거꾸로 만들면 250명이 체크인한 자리에서 287번이
나오고, "마음에 안 드니 한 번 더" 가 흔적 없이 가능해진다.

## 전체 흐름

```
구글폼 ──▶ 구글시트 ──[Apps Script onFormSubmit]──▶ POST /api/ingest/form ─┐
                                                                          │
                                                                          ├─▶ SQLite ─▶ 매칭 엔진
담당자 ─[카뱅 앱에서 거래내역 내려받기]─▶ 관리자 페이지 업로드 ───────────┤              │
                                                                          │              │
스태프 ─[접수대에서 현금·간편송금으로 받음]─▶ 관리자 페이지 현장 납부 ────┘              ▼
                                                 학생 ─[이름 + 전화번호]─▶ POST /api/status
```

카카오뱅크 개인 계좌에는 공개 API가 없고, **유심 없는 공기계로는 앱 로그인조차 되지 않아**
알림 포워딩도 불가능하다. 그래서 입금 확인은 **담당자가 거래내역 파일을 올리는 방식**이다.

즉 **실시간이 아니다.** 참가자 화면에 반영 시점(`/api/sync-status`)을 그대로 표시해
"돈 냈는데 미납으로 뜬다"는 오해를 막는다. 기간이 겹치게 다시 올려도 중복은
거래 후 잔액 기반 지문으로 흡수된다.

**당일 행사라 문 앞에서 내는 사람이 반드시 나온다.** 그때 계좌로 다시 보내게 하면
거래내역 파일을 또 내려받아 올릴 때까지 확정이 열리지 않아 줄이 선다. 그래서 받은 즉시
관리자 화면에서 입금 1건으로 남기는 **현장 납부**를 둔다. 출처가 따로 남아 정산할 때
계좌로 들어온 돈과 손에 쥔 현금을 갈라 볼 수 있다.

설계 근거와 매칭 4단계 폴백은 [BackEnd/README.md](BackEnd/README.md) 참고.

## 시작하기

```bash
# 백엔드
cd BackEnd
python -m venv .venv && .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # SECRET_KEY / ADMIN_PASSWORD_HASH / STAFF_PASSWORD_HASH / INGEST_TOKEN
python wsgi.py                # http://127.0.0.1:8000

# 프론트엔드 (다른 터미널)
cd FrontEnd
npm install
npm run dev                   # http://localhost:5173
```

관리자 비밀번호 해시는 `python BackEnd/scripts/hash_password.py` 로 만든다
(국원용은 `--staff`).

관리자 로그인은 **ID + 등급별 비밀번호**다.

- **비밀번호는 두 개다.** 최고 관리자·국장단이 쓰는 것(`ADMIN_PASSWORD_HASH`)과
  국원이 쓰는 것(`STAFF_PASSWORD_HASH`). 어느 쪽을 요구할지는 그 계정의 역할군에
  매긴 등급이 정하고, 등급이 어긋난 로그인은 서버가 거절한다.
- **ID 는 이름표다.** 같은 등급 안에서는 남의 ID 로도 들어올 수 있다. 나눈 목적은
  작업 기록에 &lsquo;admin&rsquo; 대신 그 사람의 이름이 남게 하는 것이다.

최고 관리자 ID 는 `wont0309` 이고, 나머지는 관리자 &gt; 관리자 탭에서 본인 이름으로
계정을 만들어 준다.

## 아직 비어 있는 것

새 행사의 내용이 확정되지 않아 **비워 두고 화면에서 막아 둔 것**들이다. 빈 화면 대신
&lsquo;준비 중&rsquo;을 띄우는 이유는, 지난 행사의 값이 그대로 서 있으면 그것을 보고
움직이는 사람이 생기기 때문이다.

| 무엇 | 지금 | 채우는 법 |
|---|---|---|
| 행사 정보 | `FrontEnd/src/data/event.ts` 에 `TODO` | 이름 · 일시 · 장소 · 계좌 · 폼 링크를 채운다 |
| 타임테이블 | `/schedule` 이 &lsquo;준비 중&rsquo;, 메뉴에서도 빠짐 | `data/timetable.ts` 를 채우고 `NAV_LINKS` 의 주석을 푼다 |
| 명찰 | 관리자 &gt; 명찰이 인쇄를 막음 | 새 시안으로 `data/badge.ts` 를 맞추고 `BADGE_READY = true` |
| 내 업무 | 관리자 &gt; 내 업무가 &lsquo;준비 중&rsquo; | 새 양식을 받아 `data/staffDuties.ts` 와 `DutyPanel.tsx` 를 다시 만든다 |
| 구글폼 매핑 | 뒤풀이 문항 규칙이 `contains('뒤풀이')` | 실제 폼 헤더를 받아 `apps_script/Code.gs` 의 규칙을 확인(`previewMapping`) |

## 테스트

```bash
cd BackEnd && python -m pytest tests -q     # 226 tests
cd FrontEnd && npm run build                # 타입 체크 포함
```

데모 데이터는 `python BackEnd/scripts/demo_seed.py` 로 만든다.
신청자 8명(뒤풀이 신청자 3명 포함)을 넣고, 매칭 4단계와 뒤풀이비 합산/분할 납부가
한 번씩 나오는 카카오뱅크 형식 엑셀을 생성한다.
